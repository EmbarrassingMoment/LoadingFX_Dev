## トラブルシューティング

### Q: エディタ（PIE）でマップを読み込む間、ローディングアイコンが止まります。

仕様です。ブロッキングロード中もアイコンが動き続けるのは、エンジンの MoviePlayer が別スレッドで描いているからで、MoviePlayer はエディタ、PIE、`-NoLoadingScreen` では使えません。それ以外の機能（表示遅延、最低表示時間、ウィジェット、アセットローダー）は PIE でも動きます。ロード中に回る様子は *Standalone Game*、`-game`、パッケージ版で確認してください。そのプロセスでローディング画面を出せないときは、起動時のログに `MoviePlayer is unavailable in this process` と出ます。

### Q: 短いロードではローディングアイコンが出ません。

表示遅延によるものです。アイコンは最初の要求から **Icon Show Delay**（既定 0.5 秒）たって初めて現れるので、それより短いロードでは何も表示されません。*Project Settings > Plugins > LoadingFX* で 0 にすると即座に出ます。一度のテストだけなら、コマンドラインに `-ini:Game:[/Script/LoadingFX.LoadingFXSettings]:IconShowDelay=0` を渡しても同じです。

### Q: ロードが終わってもローディングアイコンが残ります。

1 秒以内なら最低表示時間によるものです。一度現れたアイコンは **Icon Minimum Display Time**（既定 1 秒）のあいだ表示が続くので、表示遅延を少し越えただけのロードでもチラつきません。0 にすると最後の解除で消えます。

それより長く残るなら、解除されていない要求があります。コンソールで `LoadingFX.Icon.Dump` を実行すると、有効な要求が理由・経過時間・オーナー付きで一覧されます。*Acquire Loading Icon* には、そのハンドルでの *Release Loading Icon* か、要求と寿命が合う `Owner` が必要です。*Release All Loading Icon Requests*（コンソールなら `LoadingFX.Icon.Hide all`）はすべての要求を解除します。メインメニューに戻るときなどに使ってください。

### Q: 新しいレベルを読み込んだ直後、準備が終わる前にローディングアイコンが消えます。

遷移によって要求が解除されています。遷移元のレベルの `Owner`（そのレベルのアクターや PlayerController）は遷移で破棄されるので、その要求はロードの直後に解除されます。遷移先の準備に時間がかかるなら、オーナーなしでアイコンを要求し、ハンドルを GameInstance（または GameInstance Subsystem）に保持して、遷移先の準備ができたところで解除してください。レベルブループリントの変数は遷移で失われるので、ハンドルの置き場所には使えません。

### Q: 自分のウィジェットに置いたスピナーが、マップの読み込み中に止まります。

ブロッキングロード中も動き続けるのはローディングアイコンだけです。ゲームスレッドが止まっている間はゲームのウィジェットが描かれず、プラグインはローディングアイコンだけを MoviePlayer に渡して別スレッドで描かせています。自分のウィジェットのスピナー（*LoadingFX Spinner* や、同梱マテリアルを貼った *Image*）は、ロードが終われば再び動きます。ロード中も動いていてほしいものにはローディングアイコンを使ってください。

### Q: ウィジェットの Event Tick から始めたブロッキング処理の間、ローディングアイコンが止まります。

ゲームスレッドが Slate のティックの中にいる間は、MoviePlayer が描画できません。ウィジェットの *Event Tick* と、そこから呼ばれる処理はすべてその中で動きます。そこで始めたブロッキングセクションや *Show Loading Icon* 付きの同期ロードは MoviePlayer を引き継がず、ログに `BeginBlockingSection '<Reason>': called inside the Slate tick` と出て、処理が終わるまでアイコンは止まります。ブロッキング処理はアクター、タイマー、ボタンの *On Clicked* から始めてください。

### Q: ローディングアイコンが全画面のウィジェットに隠れます。

アイコンはビューポートウィジェットの中で **Icon Z-Order** 10010 にあり、通常の小さい値で追加した HUD や、TransitionFX のウィジェット層トランジション（10000）より手前に出ます。それより大きい Z-Order のウィジェットには隠れるので、*Icon Z-Order* をそのウィジェットより大きくしてください。*Add to Viewport* は渡した Z-Order に 10 を足します。

### Q: パッケージ版でマテリアルが表示されません。

自動でクックされる同梱マテリアルは 2 つだけです。**Loading Icon Material** に設定したマテリアルと、進捗バーの既定の `M_LoadingBarFill` です。ほかの同梱マテリアルは、クックされるアセット（ウィジェットブループリント、Material Instance、*Image* のブラシ）から参照されていればクックされます。実行時にパスだけで読み込むマテリアルは、*Project Settings > Packaging > Additional Asset Directories to Cook*（詳細設定）に `/LoadingFX/Materials` などを追加してください。

### Q: アセットピッカーに同梱マテリアルが表示されません。

プラグイン自身のピッカーには常に表示されます。Project Settings の **Loading Icon Material** と、*LoadingFX Spinner* / *LoadingFX Progress Bar* ウィジェットの **Material** です。それ以外のピッカー（*Image* のブラシや自分で作ったマテリアル変数など）はエディタの **Show Plugin Content** 設定に従い、この設定は UE 5.8 より前では既定でオフです。コンテンツブラウザの **Settings** メニューからオンにしてください。マテリアルは `/LoadingFX/Materials` にあります。

### Q: ログに `Compiled the shaders of the loading icon material` と出ます。

クックしていない実行（*Standalone Game*、`-game`）では正常な動作です。エンジンはマテリアルのシェーダーを最初に描くときにコンパイルしますが、ゲームスレッドが止まっている間はそれを終えられません。そのためプラグインは、ローディングアイコンのマテリアルを読み込んだ時点でシェーダーをコンパイルします。こうしないと、最初のローディング画面にアイコンが出ません。かかる時間は数十ミリ秒、プラグインを追加した直後やマテリアルを変えた直後の初回は 1〜2 秒ほどです。クック済みのビルドと PIE では行いません。

## 仕様・挙動について

### Q: 商用プロジェクトで LoadingFX を使用できますか？

はい。LoadingFX は **MIT ライセンス**の下で公開されており、ライセンス表示を含めることを条件に、商用利用、改変、再配布が制限なく許可されています。詳細はリポジトリルートの `LICENSE` ファイルを参照してください。Fab のパッケージは無料です。

### Q: C++ は必要ですか？

いいえ。必要な機能はすべて Blueprint から使え、Blueprint のみのプロジェクトでも動きます。C++ 専用なのは一部の便利機能だけです（`FLoadingFXBlockingScope`、ローダーの C++ コールバック、`OnLoadStartedNative` / `OnLoadEndedNative` イベント）。Fab のパッケージにはエンジンバージョンごとのビルド済みバイナリが入っています。このリポジトリからプラグインをコピーする場合、C++ プロジェクトではプロジェクトと一緒にビルドされ、Blueprint のみのプロジェクトではそのエンジンバージョン用のバイナリが必要です。

### Q: 対応エンジンバージョンは？ UE 5.4 以前で使えますか？

UE 5.5〜5.8 で、Fab ではバージョンごとにパッケージがあります。それより前のバージョンには対応していません。同梱アセットは UE 5.5 で保存されており、古いエンジンでは読み込めないためです。

### Q: 対応プラットフォームは？

Win64（動作確認済み）と Linux（UE 5.5 / 5.8 のクロスコンパイルツールチェーンでコンパイル確認のみ、実機では未確認）です。この 2 つが各モジュールの `PlatformAllowList` に入っています。Mac、Android、iOS、コンソールなどそれ以外のプラットフォームではモジュールがビルドされず、プラグインを使う Blueprint はそのプラットフォーム向けの cook に失敗します。プラットフォーム固有のコードはないので、試す場合は `LoadingFX.uplugin` の各モジュールの `PlatformAllowList` にプラットフォームを足してください（未検証です）。

### Q: 専用サーバーやマルチプレイのゲームで使えますか？

専用サーバーは UI を表示しないので、`LoadingFX` と `LoadingFXBridge` モジュールはサーバーターゲットから除外されており、ローディングアイコンの Subsystem も専用サーバーでは作られません。アセットローダー（`LoadingFXLoader`）はサーバーでもビルドされます。レプリケーションはしません。ローディングアイコンとローダーはゲームインスタンスごとに動くので、各クライアントが自分のロードに対してアイコンを出します。サーバーターゲットを持つ C++ のゲームモジュールでは、`LoadingFX` への依存をサーバー以外のターゲットにだけ追加してください（[AGENTS.md](../Plugins/LoadingFX/AGENTS.md#c-setup) の *C++ setup*）。

### Q: マップ遷移のときに、プラグインが自動でローディングアイコンを出しますか？

いいえ。遷移がいつ始まり、遷移先の準備がいつ終わるかはプラグインにはわからないので、自分でアイコンを出したり消したりはしません。*Open Level* の前にアイコンを要求し、遷移先の準備ができたら解除してください。プラグインが自動で行うのは、マップのロードが始まった時点でアイコンが要求されていれば、そのアイコンをエンジンのローディング画面に描くことです。これでゲームスレッドが止まっている間もアイコンが動き続けます。ハンドルは GameInstance など、遷移をまたいで残る場所に保持してください。

### Q: マップ遷移で進捗バーを出せますか？

出せません。マップのロードや、そのほかゲームスレッドを止めるロードの進捗はエンジンが報告せず、そもそもゲームスレッドが止まっている間はウィジェットを更新できません。スピナーか不定バー（`M_LoadingBarSlide`、`M_LoadingBarStripes`）を使ってください。不定バーは *Icon Size* を 192 × 12 のように横長にすれば、ローディングアイコンとしても使えます。*LoadingFX Progress Bar* は、*Load Assets Async* など自分で始めたアセットロード用です。

### Q: マップの読み込み中に画面が黒くなるのはなぜですか？ 画像を出したり、フェードしたりできますか？

ゲームスレッドが止まっている間は MoviePlayer が別スレッドでローディング画面を描き、直前のゲーム画面は残りません。プラグインはアイコンを全画面の単色 **Loading Screen Background Color**（既定は黒、常に不透明）の上に描きます。この色は設定で変えられます。その色への切り替えと戻りは一瞬です。背景画像と、ローディング画面へのフェードイン・フェードアウトはまだありません。

### Q: 場面ごとに別のローディングアイコンを使えますか？

ローディングアイコンのマテリアルはプロジェクトで 1 つ（**Loading Icon Material**）です。要求ごとの切り替えも、実行時に変える方法もありません。見た目を変えるには、同梱マテリアルの Material Instance を作って *Loading Icon Material* に設定してください。色は *Icon Tint* でも変えられます。自分の UI で別のスピナーが必要な場所には、好きなマテリアルを設定した *LoadingFX Spinner* ウィジェットを置いてください（自分のウィジェットなので、ブロッキングロード中は止まります）。

### Q: 自作のローディング画面や、ほかのローディング画面プラグインと併用できますか？

できます。LoadingFX が MoviePlayer を引き継ぐのはローディングアイコンが要求されている間だけで、すでに用意されたローディング画面があれば手を出しません。その場合、その画面がアイコンなしで表示されます。自分で作る MoviePlayer のローディング画面に LoadingFX のスピナーを出すなら、同梱マテリアルを設定した `SLoadingFXSpinner`（C++、Slate）を置いてください。マテリアルは実時間で動くので、そこでも止まりません。

### Q: TransitionFX と併用できますか？

できます。設定は要りません。ローディングアイコンの *Icon Z-Order*（10010）は TransitionFX のウィジェット層トランジション（`WidgetZOrder` 10000）のすぐ手前なので、TransitionFX がロード中に画面を覆っている間もアイコンが見えます。ブロッキングロード中の画面は *Loading Screen Background Color* に切り替わるので、これをトランジションの色（どちらのプラグインも既定は黒）に合わせておけば、ローディング画面への切り替わりとその戻りが目立ちません。

### Q: ローディングアイコンを使うのにアセットローダーは必要ですか？ その逆は？

どちらも不要です。ローディングアイコン（`LoadingFX` モジュール）とアセットローダー（`LoadingFXLoader`）は互いに依存しないので、片方だけでも使えます。両者をつなぐのは `LoadingFXBridge` モジュールで、ロード要求に *Show Loading Icon* を付けるとアイコンが出るようにしています。設定は要りません。

### Q: *Load Assets Async* はエンジン標準の *Async Load Asset* と何が違いますか？

- 1 回の要求で複数のアセットとクラスを読み込み、要求した順に返します（失敗したものは null）。
- 進捗を出し（*On Progress*）、キャンセルできます（ノードが返すアクションの *Cancel*、または *Release Loaded Assets*）。
- 読み込んだアセットを、ハンドルを解放するか `Owner` が破棄されるまでメモリに保持します。標準のノードは何も保持しないので、どこにも保存しなかったアセットは次のガベージコレクションで解放されることがあります。
- *Show Loading Icon* を付けると、ロードの間ローディングアイコンを出します。

### Q: 進捗が 0 から 1 に一気に進みます。

進捗は「読み込みが終わった要求アセットの数 / 要求したアセットの数」です。1 件だけの要求では 0 から 1 に一気に進みます。エンジンはそれより細かい進捗を出さず、アセットの依存先も数えません。クックしていない実行では、アセットを初めて読み込むときに派生データを作ってキャッシュするため、大きなロードがしばらく 0 のまま進まず、最後に数段で 1 まで上がることもあります。

## 応用・ベストプラクティス

### Q: スピナーの色や速さを変えるには？

- **エディタで:** プロジェクトの `Content` に同梱マテリアルの Material Instance を作り、パラメータ（`PrimaryColor`、`Speed` など）を変えます。プラグインフォルダ内のアセットは直接編集しないでください。更新で上書きされます。
- **実行時に:** *LoadingFX Spinner* ウィジェットで *Get Dynamic Material* を呼び、返ってきたインスタンスで *Set Vector Parameter Value* / *Set Scalar Parameter Value* を呼びます。
- **ローディングアイコン:** Material Instance を *Loading Icon Material* に設定し、色は *Icon Tint* でも変えられます。ローディングアイコンのパラメータを実行時に変える API はありません。

ウィジェットの *Color and Opacity*、*Render Opacity*、アニメーションはどのマテリアルにも乗算されます。各マテリアルのパラメータは [AGENTS.md](../Plugins/LoadingFX/AGENTS.md#bundled-materials-loadingfxmaterials) の一覧にあります。

### Q: LoadingFX のウィジェットを使わずにマテリアルだけ使えますか？

使えます。同梱マテリアルはすべて User Interface ドメインなので、標準の UMG *Image* のブラシに設定できます。ウィジェットの *Color and Opacity*、*Render Opacity*、フェードは頂点カラー経由でマテリアルに届きます。マテリアルとそのマテリアル関数はプラグインのコンテンツなので、プラグインは有効のままにしてください。

### Q: 自前のブロッキング処理の間もローディングアイコンを動かし続けるには？

その処理をブロッキングセクションで囲みます。Blueprint では、*Acquire Loading Icon*（アイコンがすでに要求されていなければ）→ **Begin Blocking Section** → *Load Asset Blocking* などブロックするノード → **End Blocking Section** → *Release Loading Icon* を、一続きの実行の流れでつなぎます。Begin と End は同じフレームで実行する必要があるので、間に latent ノード（*Delay* や非同期ノードの出力ピン）を挟まないでください。C++ では `FLoadingFXBlockingScope` がスコープを抜けるときにセクションを終えます。詳しくは README の [ブロッキングセクション](../README.ja.md#ブロッキングセクション) を参照してください。

### Q: 自分でスピナーのマテリアルを作れますか？

作れます。ローディングアイコン、スピナーウィジェット、*Image* に使うマテリアルは、User Interface ドメインにし、時間は **Ignore Pause** を有効にした `Time` ノードから取り（そうしないとブロッキングロード中に止まります）、出力に `VertexColor` を掛け、座標は `MF_SpinnerCoords` で作って正方形でないウィジェットでも丸く保ってください。進捗ありのバーは `Progress` という名前のスカラーパラメータを読みます。詳しくは AGENTS.md の [Contract for a custom material](../Plugins/LoadingFX/AGENTS.md#contract-for-a-custom-material) を参照してください。`/LoadingFX/MaterialFunctions` のマテリアル関数は、自分の形を作る部品として使えます。

### Q: AI コーディングエージェントに LoadingFX を使わせるには？

プラグインフォルダには、AI コーディングエージェント向けの使い方ガイド `AGENTS.md` が入っています。エージェントはプロジェクト内のファイルしか読まないので、プロジェクトのルートにある指示ファイルにこのガイドへの案内を書いてください。README の [AI コーディングエージェントで使う](../README.ja.md#ai-コーディングエージェントで使う) を参照してください。
